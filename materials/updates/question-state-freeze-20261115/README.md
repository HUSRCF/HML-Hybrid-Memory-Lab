第 12/13/14 层冻结时，状态词下当前值 137→61/144、初始值 131→43/144、保护账户 144→1/144；事件词分别为 125→58、134→52、143→1/144。同一历史六答全对从 111/144 降至 1/144。完整分层表包含其他全部组和九种历史条件，不只显示主目标。

两种问法合计，正常基线 814/864，50 个错误中 49 个匹配同一账户其他版本值。冻结 12/13/14 后为 216/864，582 次输出匹配其他账户的记录值，64 次匹配同账户其他版本值，另有 2 次未见整数值。数值匹配可能同时命中多条记录；全部匹配位置均保留，不能据此推断内部真的读取了哪条证据。

全部 18 层冻结时，864 次输出均不再满足整数答案格式：862 次为 `\nassistant`，另 2 次重复问题。这是广泛的任务执行失败，不能解释成所有历史记忆已丢失。干预后缀包含问题格式及 assistant 前缀 Token，因此也不能把这类输出崩溃唯一定位为版本寻址故障。

原来两个问法都错的 17 对仅作描述：冻结 0/1/2 层可以让其中 6 对两种问法都正确，但全样本状态词同时出现 177 次退步。该子集不能代替全量评价，也不能作为方法成功的证据。全部 50 条原错误在八个条件下均有导出。

实验只使用既有 `gdn_all_tokens` 适配器。该适配器原本就在第 12/13/14 层训练，因此该组的较强敏感性不能直接称为预训练模型的固有专门分工。本轮也没有单独改变 Attention Query：下游 Q/K/V、卷积、残差及 MLP 均自然变化，不能将结果唯一解释为 Query 寻址机制。

每个正常历史先完整构建，再隔离复制供全部问题使用。只在 24 个已知后缀 Token 上使选定层实际 g=0、beta=0；答案 Token 不受此干预。问题结束时，选中矩阵与其自身问题前矩阵逐位相同，历史 12 份 KV 不变；全部本轮干预钩子和 kernel 包装在答案评分／生成前撤销，原有冻结适配器按原规则继续。没有 Oracle 读取、供体前向或答案／依赖标签驱动的策略选择。

343 项 CPU 回归在原生推理前通过，261 份测量源码保持封存。相反条件顺序各 432 次执行的八份分条件原始文件逐字节一致；正式实验对应子集亦精确重放。全部 31,104 组选中矩阵前后 SHA、124,416 条实际层门控记录、41,472 条被动 Attention 观测及源缓存证明均导出。运行耗时包含这些观测、哈希、缓存复制、答案 NLL 和生成，不能作为部署 Decode 延迟。

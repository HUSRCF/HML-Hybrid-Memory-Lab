# 正常编码后再更新：推理前登记

前轮等预算实验已完整发布，但相关事实在首次编码时也受到干预，不能唯一归因于后续更新损坏。本轮先正常编码9条SET记录，得到8个账户及目标账户的初始/当前值，再从同一完整缓存分叉，只干预后续更新。

协议：[post_encoding_update_plan.json](../../../configs/post_encoding_update_plan.json)，SHA256 `ccd180ff352e56064f1eb9bbd017e41c285f49cdf16ce39764992467d9a8bfd8`。协议早于新任务生成及任何新模型推理；当前为数据和运行实现准备阶段。

保留五个固定配置、最终step432检查点及Conda base。新生成8条事件流，种子从74000开始取既有注册输入中未出现的前8个整数。登记时旧输入索引含25目录、114文件、2240条精确前缀和7920条精确完整提示；新输入的精确不重合会在数据登记时另行检查。

每条流先正常编码9条记录，再接8或64条SET。成对尾部只有最后一条SET的对象不同：一种更新无关账户；另一种更新目标账户。记录数、Token数、值和其他内容匹配。分别比较原生更新、仅关闭衰减、仅关闭Delta、两者均关闭；写入控制只覆盖尾部，不访问问题、角色、答案或支持位置。

同一份尾部后缓存回答当前、初始、无关事实三个角色的两种文体，并交叉完整读取和后见Oracle读取。问题阶段部署的适配器在问题到来前保持关闭，不用未来问题确定写入策略。前缀48个张量及完整元数据不被分叉或查询修改，12项旧KV前缀切片在所有尾部条件下完全相同。两门均关闭时18个递归矩阵应与编码后的前缀完全一致；卷积缓存仍继续运行。

正式读出8160次，其中编码后、尚未接尾部的480次，接尾部后的7680次；唯一任务问题240个，同一问题跨条件不算新独立样本。另有两轮相反模型顺序的各510次smoke、160项完整尾部no-op缓存/输出检查、320项no-op读出，以及每次运行240项旧完整运行端点检查，均与正式计数分开。

相关尾部的新当前值本来需要编码尾部证据，单独报告为正确更新对照；历史与无关事实以及无关尾部的当前值，其证据已在共享前缀中正常编码。不能将“冻结所有状态”在旧事实上的效果视为完整更新方法。

本轮按固定数据和源代码闭包登记，保留此前197份测量源码，新增9份共206份。完整前缀/尾部/问题的分块位置固定，不要求与单次整段prefill数值完全等同，也不根据任务结果调整容差。全量报告前后答案、退化、角色、文体、长度及事件流，不剔除编码后就答错的样本。

这是冻结模型的机制诊断。没有新架构成功门槛、显著性声明或训练/扩模触发条件。尾部门控仍会影响后续Query、隐藏表示、卷积和尾部KV；旧KV相同不等于唯一定位到状态矩阵存储。仅比较接尾部前后还会混入距离/位置变化，主要因果对照使用相同尾部Token和位置。

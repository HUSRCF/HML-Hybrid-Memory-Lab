# 共享控制器训练时段匹配对照

上一轮的同检查点部署消融使联合正确率从 17/48 降到 0/48，但控制器原本采用全时段训练。因此还不能区分前缀处理的作用与训练／部署时段失配。

本轮在新训练前登记了 [固定方案](../../../configs/matched_shared_training_timing_plan.json)，增加仅问题及答案阶段、仅事实前缀阶段两组共享控制器。两组均从原 seed1701 初始化开始，保持 group3、rank64、694272 个参数，以及原样、原顺序的 864 条训练样本。

每组固定 432 次 AdamW 更新、梯度累积 2、527808 个输入 Token、3456 个答案及换行 Token。检查点固定为 144、288、432，评估只使用最终 432 步。拟合较差也保留结果，禁止据此加训练、改变超参或选择中间检查点。已有主干和环境保持不变。

随后用三种训练时段与三种部署时段组成完整 3×3 对照，并保留全部八种原有基线。唯一新测试批次固定为种子 63000–63007，涵盖三档依赖深度、两种问题措辞和 8/64 次干扰更新：共 16 组、5376 次完整回答。新批次只在两组训练及其独立审计完成后生成，不用于选择参数。

两组真实单步安全检查和独立审计通过后才开始训练。最终检查全部优化器／RNG 状态、完整训练拟合、两个开发顺序、原生权重指纹、实际投影启用区间和问题阶段的完整原生前缀。新测试前还需两轮各 288 次运行检查及严格跨顺序等价校验。

这是训练时段机制对照，没有实现显式语义依赖约束。原有失败判据继续保留，普通局部适配器仍是必需的强对照。当前状态见 [进度记录](../../../configs/experiment_progress.json)。

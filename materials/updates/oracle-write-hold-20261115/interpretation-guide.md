# 正式结果汇总前的解释约束

这份补充说明不改变冻结协议、180份主运行源码、数据、配置、门控规则或旧判据。全量运行尚未完成时整理，适用于全部结果。

本轮同时令无关记录位置的衰减和写入停止，因此不能区分全局衰减、Delta擦除/写入、Key几何各自的贡献。GDN输出仍读取状态，短卷积继续处理所有Token；后续层可以把变化重新写入状态或历史KV。不能把它简写成删除无关事件或隔离纯递归回答。

支持标签是依赖后续具体问题的后见Oracle。若有改善，还需要同预算随机或位置匹配的阻断控制，才能区分语义依赖选择与单纯减少更新次数；还需另行分解衰减和写入。不得把当前结果直接包装成可部署的语义作用域控制器。

若下降，也可能因为模型依赖每步更新的背景计算或门值分布改变。它只反驳“在这个冻结模型、这批输入上，用这种强阻断就能修复”的具体假设，不能据此证明所有干扰机制不存在。

`full/oracle`两条件必须逐题精确重现先前读出。`hold/hold_oracle`改变历史GDN计算，因此下游上下文化KV也可改变。独立的120项缓存证明仅确认：在每种更新策略内部，单独改变问题阶段的读取掩码，不会改动历史48项缓存、元数据、前缀logits或12项历史K/V切片。它不要求不同更新策略之间的缓存相等。

两个因素的损失交互按预登记公式报告，但存在非线性与损失下限，不能仅凭正负号宣布两条记忆路径冗余、互补或存在语义损伤。

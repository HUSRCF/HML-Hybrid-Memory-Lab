# 推理前判断规则

1. 全部五配置、四个控制族、两种读取条件保留；不把两随机种子当作新独立事件流。八条源流及其相关变体的限制不变。
2. 首先在相同读取条件下比较控制写入与原支持写入，再与原生不抑制更新比较。只在Oracle下的效果必须保留该条件。
3. 同时查看当前、历史和无关事实及六项联合准确率；当前答案净增益不能抵消其他事实损失。
4. 随机/位置选择可能偶然保留全部或部分支持记录，全部报告其重叠、相同掩码次数与逐题结果，不排除巧合成功，也不刻意选择错误证据。
5. 整条记录、操作类型和Token数匹配，避免控制策略更容易碎片化输入更新的混淆；仍不将预算数量解释为相同状态写入能量。
6. Oracle写入优于全部控制，支持当前条件下选择身份的重要性；不足以证明自然记忆损坏、完全排除位置或得到可部署控制器。控制与Oracle相近会削弱语义选择必要性，不能改用其他指标宣布成功。
7. 前缀/预算组内掩码固定，并不代表全部问题共享同一前缀状态，因为预算本身由后续问题决定。明确保留该后见信息，不把联合分数当作统一在线记忆证明。
8. 所有损失交互仅描述，完整原始数值保留。原理想FP32内核校验失败、其数值参考修正和此前科学失败门槛不变；不因Oracle最大值触发新训练或扩模。

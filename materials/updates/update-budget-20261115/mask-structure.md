# 锁定数据的结构限制

在两轮 smoke 后、正式测量前，只读取已锁定的 policies.json 做组合数量检查，未读取任务预测，也未改变掩码或原协议。逐项数量与源码见 [结构审计](update-budget-mask-structure-20261115-01.json)。

全部336个物理问题恰好允许写入一条 SET；候选 SET 数量为16、17、72或73。本轮四类控制实际改变的是这条 SET 的身份。

COPY 预算则为零或包含该前缀全部 COPY，因此每个 COPY 分层都只有一种合法选法。四类控制在全部336个问题上的 COPY 选择均与原支持策略相同。匹配操作类型的数量在这里已经给出了是否保留整条 COPY 链，**本轮不能证明控制器学会发现依赖链，也没有检验多条 COPY 路径之间的选择。**

这将进一步收窄最终解释：支持 SET 身份与等预算的其他 SET 身份是否不同，而不是一般性的语义集合选择。所有原定结果仍完整报告，旧失败门槛不变，不增加训练或成功阈值。

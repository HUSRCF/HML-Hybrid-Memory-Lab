控制策略为两组固定哈希随机排名，以及最早、最近完整记录。每个问题严格匹配原支持策略选中记录的操作类型、Token长度、记录数及Token数；不切碎记录。现有SET和COPY记录分别为17和21 Token，不匹配则停止登记。

四种写入策略分别交叉完整读取和固定的原始Oracle读取，共13440次新正式读出、17280相关绑定。四种历史条件`full/delta_full/oracle/delta_oracle`的6720次读出作为参考，统一表20160项不得当作20160次新测量。两组随机结果分别报告，不作为更多独立任务重复。

只在未选择记录上令beta=0，保留原生衰减、卷积、GDN读取、残差/MLP及全部六层Attention。写入和读取使用两个独立掩码：Oracle读取始终保留原支持记录，不随随机/位置选择改变。beta同时控制Delta擦除和插入。

每个控制掩码只由前缀身份、记录结构和预算数量决定，不使用问题文本/ID、查询实体、答案、支持记录身份或模型输出进行排名。预算数量本身来自Oracle，仍泄露操作要求；同一前缀不同问题可有不同预算。56个前缀对应104个前缀/预算组，各组内四种策略必须跨问题与文体共享掩码。**这不等于一个对所有问题通用的前缀状态。**

随机掩码偶然选中支持记录或完全等同原策略时必须保留，不重采样、不排除；相同写入/读取策略的五字段读出必须精确重放。报告所有角色、深度、文体、负载、事件流及退化，不从结果选择掩码、模型或阈值。

新运行前需通过真实原生内核既有十项校验、12固定控制×五配置×四历史端点的精确重放，以及两轮相反配置顺序的各720次smoke。另有240项完整历史缓存检查，覆盖每项48字段/元数据/logits及12历史KV。前轮188份测量源码和原内核参考补充登记保持原样；本轮数据闭包192份、运行闭包197份。
